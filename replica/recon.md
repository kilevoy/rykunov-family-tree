# Recon map: Genery «Древо Жизни 6» (десктоп) → веб-клон

Scope: ядро продукта — дерево, карточка персоны, добавление родственников, фото и документы, совместный доступ, экспорт, импорт GEDCOM
For: личный инструмент семьи Рыкуновых (Колок), не на продажу
Date: 2026-10-11

> **Главная находка.** Genery.com/ru — это не веб-сервис, а **десктопная программа** «Древо Жизни» (Windows/macOS/Linux, данные локально в файле `.atdb`) [1][2][5]. Веб-версии, мобильных приложений и страниц в сторах на публичных страницах нет [1]. Рамка «платформа: веб» относится к клону, а не к оригиналу: клон = веб-приложение с теми же функциями. Это снижает сложность (нет синхронизации в реальном времени), но «совместный доступ» в оригинале — костыль через общий аккаунт Яндекса [8].

Правила разведки соблюдены: только публичные страницы сайта и руководство пользователя; без входа в аккаунты, без JS-бандлов, без логов сети, без обхода сайта. Прочитано 14 страниц, скачано 5 публичных маркетинговых скриншотов.

Метки: **[факт]** — есть на источнике, **[гипотеза]** — моё предположение.

## Core loop

Пользователь вводит персон и события (рождение, брак, крещение…) в таблицы → программа вычисляет связи и родство → строит дерево, диаграммы, роспись и карту → сохраняет в PDF/SVG/PNG/HTML/GEDCOM [2][6][12].

## Flows

```
F01 Создать первую персону
    S01 → «Создать» → S09 (имя, пол, рождение) → OK → S01
    happy path clicks: ~4 + ввод [гипотеза по S01/S09]
    edge: противоречие пола и событий [6]; живой человек — «В живых» [6]

F02 Добавить родственника (отец/мать/брат/сестра/жена/муж/ребёнок)
    S01 выбрать персону → меню «Создать» (связанное с выбранным) → S09
    правила: отца/мать — если не указаны; брата/сестру — если есть хотя бы один родитель;
    жену только мужчине, мужа только женщине; ребёнка нельзя при неизвестном поле [6]
    edge: связать с уже существующим — не меню «Создать» (оно всегда создаёт нового), а S09 → поле «Отец: нет данных» → выбор в таблице [6]
    happy path clicks: не измерял [нет данных]

F03 Связать с существующей персоной / роль (крёстная и т.п.)
    S09 → вкладка «События» (S10) → S20 → «роль» → выбор человека [6][12]
    edge: человек не может быть в одном событии дважды; роли «один участник» блокируются [12]

F04 Прикрепить фото и документы
    S11/S04 → выбрать файл → копия в папку «<файл>.files» [7]
    → (опц.) S21: рамка на человека → имя и возраст при наведении [7]
    → (опц.) назначить фрагмент основным фото в S09 [7]
    edge: переименовали файл данных, но не папку — предупреждение [7]

F05 Построить и сохранить дерево
    S01 → «Построить древо» → S02 → «Настройка древа» (S17) → «Сохранить древо» (S24) [2]

F06 Совместная работа
    общий аккаунт Яндекса → «Сохранить в облако» (S25) → родственник «Открыть из облака»
    параллельно редактировать нельзя: второй видит «Только чтение»; файл блокировки «.~lock» [8]

F07 Экспорт GEDCOM
    Файл → Экспорт → S22 (параметры) → UTF-8 файл + папка «.files» [11]

F08 Импорт GEDCOM
    Файл → импорт → S23 (GEDCOM 5.5.1) [9]
    edge: кодировки, потери данных — на странице не описаны [9]
```

## Inferred data model

Основа — [6][7][10][12][13] (факты) и скриншоты; типы полей — **гипотеза**.

```
Person    id, фамилия, имя, отчество, пол, живой(да/нет), «дети есть/нет», основное_фото(документ+фрагмент),
          конфиденциальность(0–10), достоверность, фаворит, род_id, место_жительства_id, занятие, комментарий,
          пользовательские части имени (напр. «Прозвище»)
          evidence: S09, S01, [6]; confidence: high
Event     id, тип_события, дата, место_id, фаворит, комментарий, конфиденциальность, достоверность
          evidence: [12], S14; confidence: high
Participation  event_id, person_id, роль (Отец, Мать, Жена, Крёстная мать…)
          правила: персона один раз на событие; некоторые роли — один участник
          evidence: [12], [6]; confidence: high
          (рождение связывает ребёнка с отцом/матерью через роли; брак — гипотеза: роли «муж/жена»)
Family(Род)    id, название — группа родственников под одной фамилией [13]; confidence: high
Document  id, файл (копия в «<имя>.files»), дата, место/координаты, отметки людей: [person_id, рамка(x,y,w,h)]
          evidence: [7]; confidence: high (рамка как x,y,w,h — guess)
Place     id, название (+ устаревшие названия), координаты [7][12]; confidence: medium
Source / SourceLink   id, описание; ссылки из персоны/события/документа [6]; confidence: medium
Task      id, текст, выполнена; привязка к персоне/событию [6]; confidence: medium
EventType id, название, фаворит(да/нет), набор ролей [12]; confidence: medium
Дата      приблизительные/диапазоны/юлианские+григорианские («26(06).05(06).1799», «ст») [S14, S09, 11]
          evidence: скриншоты; confidence: high что поддерживается, формат внутри — не известно
```

Relationships: Person n–m Event через Participation; Person n–1 Family; Event n–1 Place; Person/Event/Document n–m Source; Person/Event n–m Document; Task n–1 Person|Event. Родство (отец/мать/сестра/жена/дети) **вычисляется из событий** (гипотеза по [6][12]: отец/мать задаются в событии «Рождение»).

## Out of scope (cannot or should not be cloned)

- Код, формат `.atdb` и бинарники программы, её иконки, шрифты, тексты интерфейса и справки, скриншоты — только референс; в клон не идёт.
- Реестр российского ПО, лицензирование, продажа, форум, поддержка, сообщество 2002 года.
- Яндекс Диск как хранилище — чужой сервис; в клоне заменить своим хранилищем.
- Данные пользователей и пример «Пушкин» (портреты — внешние материалы).
- Обработка внешних карт — зависит от сторонних сервисов (в оригинале выбираются в настройках [7]).

## Size

Screens 26, flows 8, entities ~9. Hard parts: (1) граф дерева (раскладка, поколения, свёртка ветвей, браки/разводы/приёмные), (2) модель событий с ролями + вычисление родства и русских степеней родства, (3) GEDCOM 5.5.1 импорт/экспорт без потерь + даты (юлианские, приблизительные, диапазоны) + кодировки. Для совместной работы — права и блокировки (проще, чем у оригинала).
Size: **L** (квартал) для полного паритета; **M** (несколько недель) для ядра: персоны, события, дерево, фото, GEDCOM, права для семьи.
